WHAT IT DOES

Built for the Whole Pipeline

Engineered specifically to solve the data quality and rate-limiting hurdles of large fandom archives.

⚡

Dual Crawl Modes

Discover every article automatically via the allpages API with apcontinue pagination, or supply a custom URL list — one URL per line, or uploaded as a .txt file.

🧹

7-Step Sanitization

Strips ads, nav boilerplate, translator comments, chapter stubs, short junk lines, and collapses whitespace — preserving only clean, high-value article prose.

📡

Real-Time SSE Streaming

Pause, resume, or stop any crawl mid-flight. A live terminal console streams color-coded progress events from server to browser over Server-Sent Events.

📑

Auto Table of Contents

Every export opens with a linked TOC — clean Markdown anchors for .md exports, structured headers for .txt — so the corpus is immediately navigable.

🛡️

Rate Limit Resilience

Built-in 3-tier exponential backoff on HTTP 429s ($1\text{s} \to 2\text{s} \to 4\text{s}$), configurable politeness delay (0.5s–10s), and redirect-loop suppression protect every long crawl.

🪟

Safe on Windows & Linux

Explicit file-handle management, gc.collect() before cleanup, and startup orphan purging ensure zero leftover scratch directories on any OS.

HOW IT WORKS

From Wiki URL to Clean Corpus

A seamless 4-step pipeline designed for zero-friction extraction.

1

Configure

Enter a wiki URL or upload a URL list. Choose format (Markdown or Plain Text) and crawl politeness delay.

2

Discover

Crawler queries MediaWiki Action API, collects all article titles via allpages with automatic pagination.

3

Extract

7-step pipeline cleans each page body. Progress and status counters stream live to your browser over SSE.

4

Download

Click Download. The server streams the compiled file to your device and automatically purges scratch folders.

UNDER THE HOOD

Designed for Reliability

Thread-safe concurrency with strict MediaWiki Action API integration.

3-Tier
429 Backoff
7-Step
Sanitizer
SSE-Native
Streaming

FallenWiki Crawler utilizes an asynchronous FastAPI backend paired with a synchronized thread-pool worker. State transitions (running, paused, stopped) are guarded by a dedicated global threading.Lock (_job_lock) to prevent race conditions.

Scratch files are written to isolated fandom_data_{uuid} directories mapped strictly by job_id. Temporary files are safely unlocked with gc.collect() before removal, preventing OS lock conflicts on Windows.
